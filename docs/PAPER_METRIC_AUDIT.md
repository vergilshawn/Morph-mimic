# ACP 指标、坐标与目标冲突审计

审计日期：2026-10-28。对象包括冻结的 `reference_teacher_v2` 基线及已实现的 `reference_teacher_v3` 接触增强方案；本报告不等于新策略已完成箱攀。机器记录：[`acp_metrics.json`](../runs/_reports/paper_alignment/acp_metrics.json)。基线审计核对了 27 个参数值与 25 个冻结源码哈希，均一致；参数一致不能证明控制成功。V3 的最终物理启动门禁与保存/恢复检查另行记录。

论文 Fig.7 的类别成功容差为水平 0.5m；坐下、站起、起身使用垂直 0.1m。类别统计汇集三个评估 seed 的 3000 个 episode，单项/路线使用 1000 个 episode，并报告不确定性。评估时关闭噪声、动力学随机化、动作延迟。不能把三个检查点称为三个 seed，也不能把单箱单 clip 通过称为全论文复现。参考配置完整基准是 123 种，Stage 3 为 32 种。[原文评估说明](https://arxiv.org/html/2610.31608v1#S0.SS3)

本地还发现了实际目标冲突：原动作末帧的脚部几何“接近箱顶”并不代表该姿态适合静止保持。[稳定末帧报告](../runs/_reports/preflight/stable_hold_endpoint.json) 使用同一套 5mm 平面候选筛选，原 CoM 投影相对支撑凸包余量为 **−5.20cm**，优化后的几何目标为 **+3.204cm**。另一套 20mm 平面容限诊断得到原值约 −4.31cm；两者均在支撑域外，不能混用为同口径的前后值。优化后的数值是几何潜力，不是已证明动力学平衡或真实受力解。

V3 将原动作的 **501 帧全部保留**，另外追加 50 帧平滑收敛到新几何目标，生成 551 帧、11 秒的独立数据，再执行额外 50 个控制步、1 秒的真实保持。已逐数组检查原有 8 个时序数组的前 501 帧完全一致；[派生数据记录](../datasets/g1_box_climb_contact_v3/climb_03_z_scale_1.0_scene_fit_0000_0501_settle_v3.settle.json) 和独立场景/标签哈希保留来源。追加的 settle 是本地工程补充，**不是作者发布的原论文动作**。新整段几何检查通过仍不等于能物理跟踪，正式验收继续要求完整起点和全部 50 个额外物理端点通过。

## 启动前需要实际执行的冲突门禁

1. **帧一致性**：动作、几何、场景、所有指标使用同一组精确名称与环境偏移；共同参考根误差在整体平移/yaw 旋转后保持等价；局部形状误差与全局位移分列。保持段速度归零，不能把末帧外推当真实动作。
2. **作用点一致性**：保存 body 原点与机器人/场景表面点，禁止混比较；机器人局部作用点随实际末端姿态变换，表面点/法向必须对应正确障碍物及面。曲面、多面、法向不确定时标记无效，不伪装成精确平面。
3. **标签对几何**：有效接触要求命名部位、接触时段、表面距离、穿透及末端姿态可同时成立；非法标签应使门禁失败。无参考手接触时不能硬加手目标；无手指不代表手腕/前臂不可支撑。
4. **奖励相容性**：逐项验证参考状态下达到该项设计极值、可控误差使该项下降；全程不强制抬头/直立/双足落地。接触法向约束、姿态与原参考关节目标冲突时先修参考/掩码，不能靠加权掩盖。监测新增项与原 Table 3 项的数量级、`dt` 只积分一次、reset 首帧速度差有效性。
5. **真实支撑与滑动**：当前正向受力、历史接触、几何贴近分别输出；切向滑动用表面切平面投影，并只在接触有效时统计。V3 已从 PhysX 分别读取全身 30 个刚体的 normal 接触点和 friction patch，计算受力及其力臂矩；两类缓冲不按索引混配，独立扭转/滚动自由接触偶矩及机器人自接触力仍不可得。CoM 投影仍是准静态诊断，不能单独证明动态稳定。
6. **论文指标可计算性**：真实接触 onset 上先确定有效目标和一致锚点，再记录欧氏落点误差、事件数、未到达/无效/截断事件。没有有效事件时误差为缺失值而非零；无效策略计失败。保持段 `phase=1` 仍对应连续物理端点，现有只接受严格增相位的旧接触脚本不能直接处理整段保持。
7. **短物理检查**：使用独立新实验契约执行初始化、数十步 rollout、保存/恢复、完整物理评估，确认状态有限、动作真实作用、无漂浮锁根/强制重置、失败能被验收识别。静态/单元测试通过只是允许开始学习，不能要求未训练策略先完成箱攀。
8. **独立验收/不误终止**：正式学习必须持续到完整起点箱攀与真实终点保持均达标，或达到明确预算后报告失败。中段 RSI、站立辅助任务或尾段成功不算整段箱攀成功。训练前冻结新源码/数据/阈值/契约并记录哈希；旧教师权重只能按显式兼容迁移策略载入。

离线实现 `utils/contact_events.py::contact_event_report` 接收完整参考的接触时段、表面目标与法向，以及真实当前 normal-load 作用点和连续物理时间。逐 body 进行一对一时间窗/法向匹配，分别输出时间误差、空间误差、未到达事件、截断事件、不可用几何与参考覆盖率。初始已有接触不伪造 onset；保持段要求时间继续推进并显式声明物理保持。它比较参考表面事件而非 planner 指令，故明确标成工程代理，`paper_fig7_equivalent=false`；没有有效落点事件时返回缺失值，不能当零误差。

`ContactTrajectory.summary` 已接入 `commanded_landing_report`，在真实受力 onset 上比较控制开始时策略实际收到的指令锚点与该控制末端实际同部位 body 原点，直接计算米制欧氏误差及 RMSE，不匹配参考事件。V3 在 `_pre_physics_step` 进入父类前缓存输入，在该开始时根位姿下还原锚点，实际点统一减同一环境原点；缺命令、不可用实际点与首帧已存在接触分别计数。数值定义对应指令—实际 onset 误差，但本地 body-origin/normal-load 约定不等于已验证作者完整实现，单教师 rollout 也未覆盖论文的多 seed/episode 统计协议。因此输出 `kind=commanded_body_origin_onset_error`、`paper_benchmark_complete=false`；不得将机器人 body 原点与场景表面点混比。

新增指标应分别标成 `paper_metric`、`engineering_metric`、`diagnostic`，并保留 `valid`、采样范围、所需输入与未测部分。最终是否开始新训练由上述检查的实际记录决定；本审计没有启动、停止或修改训练。
